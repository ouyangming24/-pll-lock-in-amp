## 2. 排障手册

按"先看现象，再按顺序排查"组织。每步都写了**怎么判断**。

### 2.1 GUI / SDK 连不上（没有任何应答）

1. **LED1（P20）是否约 1 Hz 闪？** 不闪 → bit 没加载或时钟/复位异常，重新下载 bit。
2. **设备管理器里有 CH340 吗？** 没有 → 装驱动、换 USB 线（有的线只能充电）。
3. **串口被占用？** 报"拒绝访问"或 PermissionError → 关掉 GUI、串口助手、其他 SDK 程序。
4. **加载的是串口版 bit 吗？** 以太网版 bit 不会响应串口命令。
5. **用串口助手手工发 `stop` + 回车**（921600 8N1）：
   - 收到 `Command Success!` → 链路正常，问题在上位机
   - 无回应且 LED2（P21）不闪 → FPGA 没收到，查 TX/RX 方向（K06）和 PS UART1 冲突（K05）
   - LED2 闪但 PC 收不到回应 → FPGA 已收到（LED2 收、发都会亮），回应没到 PC，查 L17 引脚约束和 TX 线路

### 2.2 能连上，但没有数据帧（帧率为 0）

1. 发 `XYOUT` 是否回 Success？
2. 串口助手 HEX 模式，看是否有 `A5 5A A5 5A` 反复出现：
   - 有 → 上位机解析问题（帧长或格式与 FPGA 不一致？参见 2.3）
   - 没有 → FPGA 侧的帧触发 `dc_valid_x_ch1` 没有产生（通道1 IIR 不工作），检查时序报告
3. 曾经出现过的原因：注释掉 PLL 相关代码导致帧触发信号消失（issue_log 2026-05-11）。

### 2.3 有数据，但 CRC 错误一直增长

1. **不发命令时也增长吗？** 只在发命令时增长 → 正常（K04）。
2. 帧长、同步头、CRC 算法是否与 `02_通信协议_串口版.md` 一致？改过帧格式后 FPGA、GUI、SDK 必须一起更新。
3. 波特率设对了吗？必须是 921600。
4. USB 线、USB Hub 质量差会导致丢字节：直连电脑后面板的 USB 口再试。

### 2.4 PLL 锁不上 / 锁定反复跳

1. `adc[0]`（V1）或 `adc[1]`（V2）有信号吗？幅度太小（< 几十 mV）不容易锁。
2. 信号频率在扫频范围内吗？扫频范围是**起点 ±10 kHz**，起点由 `FRQ2`（通道1）/ `FRQ3`（通道2）设定。
3. 通道2 锁不上先检查是否发过 `FRQ3`（K02）。
4. 反复横跳 → 调低 `LOCKSWY` / `LOCKTHX`（默认 100000 / 300000），或加大 `TAU1Y` / `TAU2Y` 让 Y 路更平滑。
5. 锁定后频率抖动大 → 减小 `KP`、`KI`。

### 2.5 振荡器 X/Y 为 0 或恒定（通道3 异常）

1. **先看 `lock_flags`**：bit2 应为 1，bit3、bit4 应为 0，bit[15:8] 应为 0x31。
   - 不对 → AD7606C 配置失败：查供电、跳线 H5 是否已拔、并口排线
2. **看 `adc[2]`（V3 瞬时值）**：
   - 有正常波形 → ADC 正常，问题在参考频率或滤波设置（第 3 步）
   - 恒为约 8000（+9.77 V）→ K01：V3 输入悬空 / 过量程 / 接错通道。用万用表量 V3 端子电压，
     接一个已知信号（比如把 DAC 输出接到 V3）再看
3. **看帧里的 `ref_word`**：实际参考频率是你想要的吗？
   - 手动模式：是否等于 `FRQxx × OHNk`
   - 自动模式：两路 PLL 都锁定了吗？未锁定时参考频率没有意义
4. `OSRCk` 选对输入了吗（0 = V3、1 = V4、2 = V3−V4）？
5. 时间常数太大（`TAU` ≥ 20）时，输出要几秒才稳定。

### 2.6 DAC 没有输出 / 输出不对

1. `DAMP` 是不是 0？`DMOD` 选的振荡器参考频率是多少（看帧里 `ref_word`）？
2. 自动模式下，所选振荡器依赖的 PLL 没锁定时，频率会乱跳。
3. 输出被削顶 → `DAMP` 和 `DOFS` 叠加后超出 ±8191，减小幅度或偏置。
4. 满量程约 ±3 V；输出端负载太重时幅度会下降。

### 2.7 示波器没有波形 / 一直等待

1. Normal 模式（`SCAP` 的 bit3 = 1）下没有满足条件的边沿会一直等 → 先用 Auto 模式确认有信号。
2. 触发电平 `STLV` 超出信号范围？电平码 = 电压 × 3276.8 + 32768。
3. 示波器包到了吗？HEX 里找 `A5 5A 5A A5`。
4. V6 恒定约 1.93 V 是**未接信号**时的典型现象，不是故障。

### 2.8 改了 RTL，上板现象没变

这是历史上最常见的"假问题"（issue_log 多次记录）：

1. 确认下载的是**刚生成的** bit（看文件修改时间）。
2. 确认是 `design_1_wrapper.bit`，不是旧的独立顶层 bit。
3. 改了端口要 Refresh Module 并重新生成 wrapper。
4. 如果是固化启动，记得重新生成 BOOT.bin 并烧录。

### 2.9 综合 / 实现失败

| 报错 | 常见原因 |
|---|---|
| 时序 WNS < 0 | 新增组合逻辑太长 → 加寄存器打拍 |
| DSP 超出 220 | 新增 CIC / 乘法器 → 用 LUT 版 CIC（`cic_compiler_1`） |
| wrapper 版所有命令回 Error | BD 被改回了 OOC → 改回 Global（D02） |
| 对表达式位选报错 | Verilog-2001 不允许 `(a*b)[47:0]`，先赋给 wire 再位选 |
| IP 被锁定（locked） | IP 版本与 Vivado 版本不符 → Report IP Status → Upgrade |

## 3. 诊断工具

| 工具 | 用法 |
|---|---|
| 帧内 `lock_flags` | AD7606C 自检 + PLL 锁定状态 |
| 帧内 `adc[0..2]` | V1/V2/V3 原始值，判断是模拟前端还是数字处理的问题 |
| 帧内 `ref_word[7]` | 每个振荡器实际生效的参考频率，判断命令是否生效 |
| LED1 / LED2 | PL 是否运行 / 串口是否有收发 |
| ILA（`.ltx`） | `adc_ch3` / `adc_ch4` 等信号的实时波形 |
| 串口助手 HEX 模式 | 手工发命令、看原始字节 |
| `tests/fake_fpga.py` + `sdk_selftest.exe` | 排除上位机问题（不需要板子） |
| `docs/issue_log.md` | 查历史上是否遇到过相同现象 |
