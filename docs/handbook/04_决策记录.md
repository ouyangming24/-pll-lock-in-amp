# 04 决策记录

每条记录：**背景 → 决定 → 原因 → 代价**。新增决策追加到末尾，旧决策被推翻时不要删，标注"已被 Dxx 取代"。

标 **（待补充）** 的地方是根据代码和过程记录推断的，请按实际情况修改。

## D01 全部逻辑放在 65 MHz 单一时钟域

- **背景**：早期 `usb_commend` / FT245 跑在 50 MHz，处理核心跑在 65 MHz，640 位数据帧和 435 位配置总线直接跨时钟域，
  出现过振荡器2 恒为 0、串口与 UDP 数据不一致、频率乱跳（issue_log 2026-05-12、06-10、06-11）。
- **决定**：通信模块整体迁到 `clk_65M`，与处理核心同域直连，删除跨时钟域逻辑。
- **原因**：宽总线跨时钟域要么用异步 FIFO、要么握手，都会增加资源和复杂度；同域最简单可靠。
- **代价**：串口分频系数只能是整数 70，导致 +0.76% 波特率误差（见 D05）。

## D02 BD 用 Global 综合，不用 OOC

- **背景**：`lock_in_amp` 作为 BD module reference 被 OOC 综合时，内部三态总线在 IP 边界和 wrapper 各推断一层 IOBUF，
  导致 wrapper 版本所有命令都回 `Command Error!`（issue_log 2026-09-23）。
- **决定**：`design_1.bd` 的 `synth_checkpoint_mode` 设为 None（Global）。
- **原因**：现在 AD7606C 的 `ad_db` 仍是 inout 双向总线，同样的问题依然存在。
- **代价**：每次综合都要重新综合整个 BD，耗时稍长。

## D03 ADC 换成 AD7606C-16，软件模式 + 220 kHz 带宽

- **背景**：需要更多同步采样通道（PLL 两路 + 解调两路 + 示波器两路）。
- **决定**：AD7606C-16 并口，软件模式（OS=111）上电写寄存器：8 通道 ±10 V 单端、220 kHz 高带宽，并回读 ID 自检。
- **原因**：8 通道同时采样，各通道相位一致；硬件模式带宽只有 25 kHz，不够用。
- **代价**：
  - 驱动比硬件模式复杂（寄存器写入、自检）。
  - 占用了原 FT245 的引脚，FT245 通信方式无法再用。
  - 模块上短接 CONVSTA/CONVSTB 的跳线 H5 必须拔掉（CONVSTB 引脚实际是 WR）。

## D04 通信从以太网改为板载 CH340 串口

- **背景**：FT245 引脚被 AD7606C 占用后，先迁到千兆以太网 UDP（已验证的 bit 保存在 `agent-tools/eth_only_verified_bit/`），
  之后改为板载 CH340 串口（L17/M17 接 PL）。
- **决定**：命令和数据全部走 CH340，921600 8N1。
- **原因**：板上自带 CH340，一根 USB 线即可，不需要网卡、IP 配置和防火墙设置；以太网相关逻辑和时钟也能去掉，
  减轻时序和资源压力。**（待补充：当时选择串口的其它实际原因）**
- **代价**：带宽从以太网的约百 Mbit/s 降到约 0.9 Mbit/s，数据帧只能约 450 帧/秒，示波器一包要约 45 ms。
  以太网版本可以通过 `tools/eth_only_bd_update.tcl` 恢复。

## D05 波特率 921600，接受 +0.76% 误差

- **背景**：CH340 支持的标准高速波特率有 921600、2 M 等；65 MHz 时钟下分频必须是整数。
- **决定**：BPS_CNT = 70，实际 928571 波特。
- **原因**：UART 8N1 能容忍约 ±2% 的总误差，0.76% 有足够余量；921600 是 CH340 和各种串口工具都稳定支持的速率。
- **代价**：如果以后要更高速率（如 2 M），65e6/2e6 = 32.5 不是整数，误差 1.5%，余量很小，需要评估。

## D06 256 字节 RX FIFO，FPGA 发送期间不读命令

- **背景**：`usb_commend` 在发应答、发示波器包时不处理接收字节，但 PC 端不会停下来等。
- **决定**：在 `uart_link` 里加 256 字节 FIFO，`rx_ready` 为低时字节留在 FIFO 里。
- **原因**：最长阻塞是示波器包（约 45 ms）。上位机是"发一条、等应答、再发下一条"，
  阻塞期间最多积压一条命令（不到 30 字节），256 字节足够。
- **代价**：如果有人用串口助手连续狂发命令，超出 FIFO 的字节会丢。

## D07 命令可以打断数据帧，示波器包不可打断

- **背景**：数据流开着时，如果命令要等当前帧发完，GUI 点"发送"会感觉要点好几下才有反应
  （之前出现过的问题）。
- **决定**：
  - 数据帧发送中收到非 CR/LF 字节，立即中止当前帧去解析命令（PC 收到半帧，靠 CRC 丢掉）。
  - 示波器包不打断，发完再处理命令。
- **原因**：数据帧每秒几百帧，丢一帧无所谓，命令响应要快；示波器包一次抓取只有一包，被打断就要重新抓。
- **代价**：发命令时会出现少量 CRC 错误计数，这是正常现象；用户需要知道这一点，不要误以为链路有问题。

## D08 数据帧加帧序号、时间戳和 CRC16（帧协议 v2）

- **背景**：
  - GUI 用 PC 时间打时间戳，抽样保存时出现"看起来像 20 Hz 正弦波动"的假象。
  - 命令打断帧后，GUI 只校验同步头，把"半帧 + 应答 + 下一帧开头"当成一帧解析，产生尖峰。
  - 约 1.8% 的帧有个别字节被替换。
- **决定**：帧内加 `sample_cnt`（FPGA 1 MHz 节拍计数），帧尾加 `frame_seq` 和 CRC-16/CCITT-FALSE。
- **原因**：时间戳在 FPGA 侧打，与 PC 调度无关；CRC 能可靠剔除半帧和损坏帧。
- **代价**：帧从 168 字节增加到 178 字节。详见 `docs/帧协议v2_时间戳与CRC.md`。
- **附带修复**：发送模块改为在 `send_en` **上升沿**启动（原来按电平触发，每帧第一个字节会重复发送）。
  现在的 `uart_link` 沿用了这个上升沿约定。

## D09 DAC 直接复用振荡器的参考正弦，不用独立 DDS

- **背景**：早期 DAC 用独立 DDS + `DFRQ`/`DPHS`，与解调参考不同源，出现相位差、频率固定在 88 kHz、时序违例等问题
  （issue_log 2026-06-08、06-11）。
- **决定**：DAC 输出 = `DMOD` 选中的振荡器参考正弦 × `DAMP` + `DOFS`；`DFRQ`/`DPHS` 保留解析但不起作用。
- **原因**：激励与解调参考天然同频同相，测量更准；少一个 DDS 也省资源。
- **代价**：DAC 不能独立设频率，要输出某频率就得占用一个振荡器。

## D10 自动模式用 PLL 相位直接合成参考（相干本振）

- **背景**：自动模式原来只借用 PLL 的频率字驱动独立 DDS，相位与输入不相干，每次上电或切模式测得的相位都不一样
  （issue_log 2026-06-10）。
- **决定**：`coherent_harm_lo` 用两路 PLL 的相位字计算 N·(n·θ1 + m·θ2) 作为参考相位。
- **原因**：参考与被测信号相干，相位读数可重复。
- **代价**：乘加需要三级流水，自动模式下 `FRQxx` 不起作用。

## D11 振荡器 5/6/7 使用 LUT 实现的 CIC

- **背景**：振荡器从 3 个扩到 7 个后 DSP 不够（现在 DSP 已用 95%）。
- **决定**：振荡器5/6/7 的 CIC 用 `cic_compiler_1`（LUT 实现），其余用 `cic_compiler_0`（DSP 实现）。
- **原因**：CIC 是纯加法器，用 LUT 实现功能完全一样，只是多占逻辑。
- **代价**：LUT 占用升到约 70%；再加功能前要先评估资源。

## D12 IIR 用一阶 EMA 级联，tau 档位为 2 的幂

- **背景**：需要类似 SR830 的时间常数 + 6/12/18/24 dB/oct 斜率。
- **决定**：α = 2^-tau，乘法变成移位；1~4 阶级联，每路振荡器阶数独立可调。
- **原因**：不占 DSP，档位按约 2 倍步进与商用仪器习惯接近。
- **代价**：时间常数只能取约 2 倍间隔的离散档位，不能连续调。

## D13 示波器：1024 点、128 点预触发、抽取不平均

- **背景**：需要像示波器一样看 V5/V6 两路波形。
- **决定**：BRAM 环形缓存 1024 × 32 位，预触发 128 点，迟滞 64 LSB，Auto/Normal 两种模式，抽取直接隔点取样。
- **原因**：一包 4 KB 在串口上约 45 ms，刷新率可接受；隔点取样实现最简单。
- **代价**：抽取时不做抗混叠滤波，信号频率高于 1/(2×dt) 时会混叠成假波形。

## D14 C++ SDK：纯 Win32 + C++17，重叠 I/O，单接收线程

- **背景**：需要给第三方 C++ 工程做二次开发接口。
- **决定**：
  - 只依赖 Win32 API，不用 Qt / Boost。
  - 串口用 `FILE_FLAG_OVERLAPPED`。
  - 一个后台线程负责接收和解析；命令用互斥锁串行化，等应答超时 500 ms。
- **原因**：
  - 零依赖，MinGW 和 MSVC 都能编译。
  - 同步句柄下 `ReadFile` 阻塞时 `WriteFile` 也会被卡住（实测过），必须用重叠 I/O。
- **代价**：只支持 Windows；Linux 需要另写 `serial_port_posix.cpp`。

## D15 命令只用十进制正整数

- **背景**：解析器在 FPGA 里，越简单越好。
- **决定**：数字部分只认 0~9，48 位累加，其它字符忽略；负数用补码（如 `DOFS`）。
- **原因**：省逻辑，避免在 FPGA 里处理符号、小数、十六进制。
- **代价**：上位机必须先把物理量换算成整数码（频率字、补码等）。

## D16 双流模式：GUI 用 XYOUT，新 SDK 用 SDKOUT

- **背景**：新应用只要振荡器1 + V3/V4/V5；不想动 GUI；也不想再攒 1024 点示波器包。
- **决定**：
  - 保留 `XYOUT` 178 B 经典帧（GUI / `lockin_sdk_cpp`）。
  - 新增 `SDKOUT` 28 B 精简帧（`lockin_sdk_osc1`）；每帧直接带 V3/V4/V5 瞬时样点。
  - `SDKOUT` 期间丢弃 `SCAP` 上传，避免占带宽。
- **原因**：互斥流模式改动面小；同步头 `A5 5A C3 01` 与经典帧/示波器包不冲突。
- **代价**：精简帧没有其它振荡器/PLL/锁定标志；要全量数据仍用 `XYOUT`。
