## 答案

### A 部分要点

1. V1 → AD7606C → `ad7606c_drv`（取高 14 位）→ `pll_loop` 通道1（与本振 sin/cos 混频 → CIC → IIR → `pll_controller` PI 调本振频率）
   → `pll_freq_ch1` 频率字 → `lock_in_amp` 打包进帧 → `usb_commend` 加序号和 CRC → `uart_link` → CH340 → GUI `device.py` 解析
   → 频率字 × 65e6/2⁴⁸ → 乘时基标定 → 显示。
2. X 是同相分量，Y 是正交分量。只算 X 时，信号与参考有相位差 θ 就会得到 R·cosθ，幅度测小，相位差 90° 时测出 0。
   有 X、Y 才能求 R = √(X²+Y²) 和 θ。
3. 1 MHz（65 MHz / 65）。IIR 在 CIC 之后，每 1 µs 更新一次，α 的含义是"每个输入样点更新多少"，所以按 1 MHz 换算。
4. 手动：f = `FRQxx` × `OHNk`，独立 DDS。自动：f = `OHNk` × (n·F1 + m·F2)。只借频率字时独立 DDS 的初相随机，
   与输入不相干，每次上电相位读数都不同；用 PLL 相位合成，参考与输入相干，相位可重复。
5. 扫频时看 |Y| > `LOCKSWY` 进入锁定，锁定后看 |X| < `LOCKTHX` 持续约 2 s 才回扫频。
   锁定时 PI 控制把 Y 压向 0，所以锁定后 Y 不能作为维持判据；扫频时频率差大，X 来回振荡不稳定，Y 先出现明显响应。
6. 避免宽总线跨时钟域。历史上 `usb_commend` 在 50 MHz 直接采 65 MHz 的 640 位数据帧和 435 位配置，
   出现振荡器2 恒 0、串口与 UDP 数据不一致等问题。
7. 立即中止当前帧，转去解析命令；PC 收到半帧，长度不够或 CRC 错，被丢弃并计入 CRC 错误。
   示波器一次抓取只有一包，打断就白抓了，而且只占 45 ms，等一下无所谓。
8. `frame_seq` 用于发现丢帧和重复帧；`sample_cnt` 是 FPGA 侧 1 MHz 时间戳，用于生成准确的时间轴。
   FPGA 在帧间隔 0.3 ms 内仍会锁存新快照并递增序号，但只发最后一次，所以相邻帧序号差常大于 1。
9. 早期独立 DDS 与解调参考不同源，出现相位差、频率卡在 88 kHz、时序违例。复用振荡器参考：好处是激励与解调同频同相、省资源；
   代价是 DAC 频率不能独立设置。
10. `ad_db` 是 inout 双向总线，OOC 时 IP 边界和 wrapper 各推断一层 IOBUF，总线读写错乱；历史现象是 wrapper 版所有命令都回 Error。
11. 为了看到触发时刻之前的波形（比如脉冲的上升沿前）。Auto 超时无触发就强制抓一屏（`forced` = 1），Normal 一直等真实触发。
12. 隔点取样直接丢掉中间的点，高于 1/(2·dt) 的频率成分会折叠成低频假信号；先平均相当于低通滤波，可以抑制混叠。本项目示波器是隔点取样。
13. `lock_flags`：AD7606C 配置是否成功、PLL 是否锁定；`adc[2]`：V3 模拟输入本身是否正常（区分前端问题和数字问题）；
    `ref_word`：命令是否真正生效、参考频率是否符合预期。
14. 同步句柄上，后台线程阻塞在 `ReadFile` 时，另一个线程的 `WriteFile` 也会被卡住，命令发不出去；重叠 I/O 允许读写同时进行。
15. DSP 已经用到 95%，CIC 只有加减法，用 LUT 实现功能一样，只是多占逻辑资源。
