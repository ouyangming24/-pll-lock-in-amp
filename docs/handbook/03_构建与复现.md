## 2. 从源码到 bit

### 2.1 正常情况（工程完好）

1. 打开 `project_1.xpr`。
2. 如果改过 `lock_in_amp.v` 的**端口**：在 BD 里右键 `lock_in_amp_0` → Refresh Module，
   然后 Validate Design、保存 BD、重新生成 wrapper（Create HDL Wrapper，让 Vivado 管理）。
3. Generate Bitstream。产物：`project_1.runs/impl_1/design_1_wrapper.bit`。
4. 检查时序：Open Implemented Design → Report Timing Summary，WNS、WHS 都必须 ≥ 0。

只改模块内部逻辑、不改端口时，第 2 步可以跳过。

### 2.2 从以太网版切到串口版（或 BD 乱了）

在 Vivado Tcl Console 执行：

```tcl
source E:/company/Aunion/Lock_In_Amp/FPGA-2/git_pll/tools/uart_only_bd_update.tcl
```

脚本会启用 `uart_link` / `uart_rec` / `uart_send`、停用以太网源文件和 `clk_wiz_eth`、
刷新模块引用、删除 `eth_*_0` 端口、引出 `uart_txd_0` / `uart_rxd_0`、校验并重新生成 wrapper。
然后 Generate Bitstream。

切回以太网：还原 `lock_in_amp.v` / `pin_solidify.xdc`（备份在 `agent-tools/backup_before_uart_only_10231638/`），
再执行 `tools/eth_only_bd_update.tcl`。

### 2.3 必须保持的设置

- **BD 综合方式必须是 Global**（`synth_checkpoint_mode None`），不能是 Out-of-Context。
  原因：`ad_db` 是 inout 总线，OOC 下 IOBUF 推断失败。
- `uart_rxd_0` 的 PULLUP 在 `pin_solidify.xdc` 里，CH340 未上电时防止误收。

### 2.4 当前已验证版本

`agent-tools/uart_only_verified_bit/` 保存了一份上板验证过的串口版产物：

| 文件 | 内容 |
|---|---|
| `design_1_wrapper.bit` / `.ltx` | bit 与 ILA 探针文件 |
| `timing.rpt` | WNS = 1.436 ns，WHS = 0.035 ns（保持时间余量很小） |
| `util.rpt` | LUT 69.9%，FF 23.7%，BRAM 24.6%，**DSP 95%（209/220）** |

DSP 已经快用完，再加振荡器或滤波器必须先想好资源（见决策记录）。

## 3. 下载与固化

### 3.1 临时下载（JTAG，掉电丢失）

Vivado → Open Hardware Manager → Auto Connect → Program Device，选 `design_1_wrapper.bit`
（和 `.ltx`，需要看 ILA 时）。

注意：PL 的 65 MHz 时钟来自板载 50 MHz 晶振，不依赖 PS，所以只下 bit 也能工作。

### 3.2 固化到 Flash / SD 卡

本机日常工作区：`E:\company\Aunion\Lock_In_Amp\FPGA-2\solidify_lock`（Platform 名 `platform`）。
BOOT 内容与手工一致：**仅 fsbl.elf + bit**（无应用 elf）。

#### 推荐：一键脚本（改完 HDL 后）

```powershell
cd E:\company\Aunion\Lock_In_Amp\FPGA-2\git_pll
# 全流程: Vivado 出 bit/XSA → 更新 Vitis Platform → bootgen → 拷到 SD
.\tools\rebuild_sd_boot.ps1 -SdDrive E:

# 已在 Vivado GUI 里出过 bit/XSA，只刷 Platform + BOOT
.\tools\rebuild_sd_boot.ps1 -SkipVivado -SdDrive E:

# 或双击 / 命令行
.\tools\rebuild_sd_boot.bat E:
.\tools\rebuild_sd_boot.bat -SkipVivado E:
```

脚本位置：`tools/rebuild_sd_boot.ps1`（编排）、`vivado_build_export.tcl`、`vitis_rebuild_platform.py`。
输出：`solidify_lock\boot\BOOT.bin`；指定 `-SdDrive` 时再拷到卡根目录。
日志：`tools\_vivado_build.log`、`tools\_vitis_rebuild.log`。

Xilinx 安装路径写死为 `D:\software\xilinx\2025.1\`；换机器改 `.ps1` 顶部三行路径。

#### 手工步骤（首次建工作区 / 排查）

1. Vivado：File → Export → Export Hardware，选 **Include bitstream**，得到 `design_1_wrapper.xsa`。
2. Vitis 2025.1：用该 XSA 新建 Platform（OS 选 standalone，勾选生成 FSBL），Build。
3. Create Boot Image：`fsbl.elf`（bootloader）→ `*.bit`，生成 `BOOT.bin`（可不带应用 elf）。
4. SD：BOOT.bin 拷到 FAT32 卡根目录；拨码 SD 启动，上电看 LED1（P20）约 1 Hz 闪烁。

参考 bif：`solidify_lock\boot\BOOT.bif`；脚本会另写 `BOOT.auto.bif`。

## 4. 上板验证（最小检查）

1. 上电：LED1 约 1 Hz 闪 → PL 在跑。
2. USB 接 CH340，设备管理器出现 `USB-SERIAL CH340 (COMx)`。
3. 打开 GUI（串口模式）点连接。GUI 会发 `stop` 握手（最多 3 次），收到应答才算连上；LED2 闪一下。
4. 开数据流：帧率约 450 帧/秒，CRC 错误不持续增长。
5. 看 `lock_flags`：bit2 = 1、bit3 = 0、bit4 = 0、ID = 0x31 → AD7606C 配置正常。
6. DAC 输出接 V1 或 V5，用示波器窗口看 V5 波形，或看通道1 是否锁定。

## 5. Python GUI

### 5.1 直接运行

```bat
cd lockin_gui
python -m pip install -r requirements.txt
python main.py            :: 串口模式（默认）
python main.py --udp      :: 以太网模式（旧 bit）
python main.py --demo     :: 演示模式（不需要板子）
```

### 5.2 打包绿色版

```bat
cd lockin_gui
build_portable.bat
```

脚本用 `lockin_gui.spec` 调 PyInstaller，输出 `dist\LockinGUI\`，并拷入 `portable_assets\` 里的
启动脚本和说明。**打包前先备份旧的 `dist\LockinGUI`**（脚本会直接删除它）。
上一版以太网包备份在 `dist\LockinGUI_old_udp_1020\`。

目标电脑只需要：整个 `LockinGUI` 文件夹 + CH340 驱动。

## 6. C++ SDK

### 6.1 编译

```bat
cd lockin_sdk_cpp
build_mingw.bat
```

输出 `build_mingw\` 下的 `liblockin_sdk.a`、`lockin_demo.exe`、`sdk_selftest.exe`。
脚本会自动找 Vivado 自带的 MinGW；换电脑时改脚本里的路径或把 g++ 加进 PATH。

CMake（MSVC 或 MinGW）：

```bat
cmake -S . -B build && cmake --build build --config Release
```

本机 VS2022 没装"使用 C++ 的桌面开发"组件，MSVC 路径**未实测**。

### 6.2 无板子自测（虚拟串口）

需要一对虚拟串口（本机用 ELTIMA 建的 COM1↔COM2）：

```bat
:: 终端 1：假 FPGA 守在 COM2
python tests\fake_fpga.py COM2

:: 终端 2：SDK 连 COM1
build_mingw\sdk_selftest.exe COM1
```

全部 PASS 说明 SDK 的命令编码、应答处理、帧解析、示波器包解析、CRC 都正确。
`fake_fpga.py` 会把收到的命令写进 `fake_fpga_cmds.txt`，可以逐条核对。

### 6.3 上板测试

```bat
build_mingw\lockin_demo.exe          :: 自动找 CH340
build_mingw\lockin_demo.exe COM5     :: 指定串口
```

demo 会设置振荡器、DAC 输出 1 Vpk、抓两次示波器存 CSV、收 2 秒数据流。
运行前关掉 GUI 和串口助手（串口独占）。

## 7. 仿真

`project_1.srcs/sim_1/` 下只有顶层级的 `pin_solidify.v` / `eht_pin_solidify.v`，没有系统的模块级 testbench；
验证 `usb_commend` / `uart_link` 这类模块时，临时写 testbench 用 xvlog/xelab/xsim 跑即可。
注意：xvlog 对 `initial` 块里字符串常量 `"\r"` 的处理与综合不同，仿真波形里应答结尾显示为 `r`，
**上板实测是正常的 CR**，不要被误导。
