## 2. AD7606C 的接口和跳线

### 2.1 用的是并口，不是 SPI

现在用的是 AD7606C 的 **16 位并行接口**：16 根数据线 `ad_db[15:0]`，加上 CONVST、BUSY、CS、RD、WR、
RESET、FRSTDATA、OS[2:0] 等控制线。读一次传一个通道的完整 16 位。

| 信号 | 方向 | 作用 | FPGA 引脚 |
|---|---|---|---|
| `ad_db[15:0]` | 双向 | 数据总线：配置时 FPGA 写，采样时 FPGA 读 | A16 A17 C20 D20 C15 B15 D16 D17 E15 D15 C19 D18 F16 E16 G16 G15 |
| `ad_convst` | FPGA → 芯片 | 上升沿启动 8 路同时转换 | B16 |
| `ad_busy` | 芯片 → FPGA | 转换中为高，完成后变低 | B21 |
| `ad_cs_n` / `ad_rd_n` | FPGA → 芯片 | 片选 / 读脉冲 | B22 / C22 |
| `ad_wr_n` | FPGA → 芯片 | 写脉冲（只在配置寄存器时用） | E19 |
| `ad_reset` | FPGA → 芯片 | 完全复位 | D22 |
| `ad_os[2:0]` | FPGA → 芯片 | 固定输出 `111`，选软件模式 | G19 F19 E20 |
| `ad_frstdata` | 芯片 → FPGA | 读 V1 时为高，用于检查读数是否错位 | B17 |

### 2.2 模块跳线

模块上 REF_SEL、PSB_SEL、RANGE 三个脚 FPGA 没有接，分别由 1×3 跳线 H1、H2、H3 决定电平。

| 跳线 | 芯片引脚 | 作用 | 本项目设置 |
|---|---|---|---|
| H1 REF_SEL | REF SELECT（34 脚） | 高 = 内部 2.5 V 基准；低 = 关闭内部基准，必须从 REFIN/REFOUT 外接基准 | **接高** |
| H2 PSB_SEL | PAR/SER SEL（6 脚） | 低 = 并口；高 = 串口。完全复位释放时锁存 | **接 GND** |
| H3 RANGE | RANGE（8 脚） | 硬件模式下选量程（高 ±10 V，低 ±5 V）；**软件模式下被忽略**，但不能悬空 | 接高或接低（建议接高） |
| H5 | CONVSTA–CONVSTB | 见 2.3 | **拔掉** |

设置错误时的现象：
- REF_SEL 接低但没外接基准：ADC 没有参考电压，读数乱或卡在固定值。
- PSB_SEL 接高：FPGA 按并口时序读，全部读错，`cfg_err = 1`，`dev_id` 不是 0x31。
- RANGE 悬空：违反数据手册要求，状态不确定。

### 2.3 为什么 H5 必须拔掉（CONVST 与 WR 不能相连）

这块模块原本是为老款 AD7606 设计的，老款有 CONVSTA、CONVSTB 两个转换脚，H5 短接让 8 路同时采样。
AD7606C 只有一个 CONVST，原 CONVSTB 那个脚（10 脚）变成了 **WR**。H5 短接就等于 CONVST 和 WR 相连。

数据手册原文：*"In hardware mode, the WR pin has no function. Therefore, the WR pin can be tied high, tied low,
or shorted to CONVST. In software mode, the WR pin is the active low write pin for writing registers."*

本项目是软件模式，短接会造成：

1. **电气冲突**：B16（CONVST，多数时间输出低）和 E19（WR，一直输出高）两个推挽输出对拉，
   约 88% 的时间相当于电源经两个 IO 短路，线上是 1.65 V 左右的中间电平，长期可能损坏引脚。
2. **配置失败**：每个 WR 脉冲同时变成 CONVST 边沿，写寄存器时启动转换，`cfg_err` 可能置 1。
3. **采样数据错乱**（按数据手册的寄存器访问规则推断）：每次 CONVST 时芯片看到 WR 边沿，
   把数据线上残留的内容当成寄存器命令锁存。残留值多半是上次读出的 V8，V8 为负时最高位是 1，
   可能被当成"读寄存器"命令进入寄存器模式，之后读到的就是寄存器内容而不是采样值。

检查方法：万用表蜂鸣档量模块 P3 上的 CONVST 和 WR，不应导通；上电后 `lock_flags` 正常（见第 4.4 节）。

## 3. 上电初始化

驱动是一个 5 状态的状态机：

```
上电 ──▶ ST_PWRUP ──▶ ST_RESET ──▶ ST_SETUP ──▶ ST_CFG ──▶ ST_RUN（一直循环采样）
         等 10 ms     RESET 高 4 µs   等 300 µs    写/读寄存器    每 1 µs 采一次
```

| 状态 | 时长 | 动作 | 数据手册要求 |
|---|---|---|---|
| `ST_PWRUP` | 10 ms | 等电源稳定 | tPOWER-UP ≥ 10 ms |
| `ST_RESET` | 4 µs | `ad_reset` 拉高 | 完全复位 ≥ 3.2 µs |
| `ST_SETUP` | 300 µs | 等待 | tDEVICE_SETUP ≥ 274 µs |

芯片在**复位释放那一刻**锁存工作模式（OS 引脚决定软件/硬件模式，PAR/SER SEL 决定并口/串口），
所以 `ad_os` 从上电起就固定输出 `111`，不能等配置时才给。

从上电到开始采样约 10.3 ms。

## 4. 寄存器配置（`ST_CFG`）

### 4.1 并口寄存器访问格式

```
 DB15      DB14 ~ DB8      DB7 ~ DB0
 R/W       寄存器地址        数据
(1 = 读)    (7 位)          (8 位)
```

### 4.2 十条配置操作

| 序号 | 操作 | 写入 / 期望值 | 含义 |
|---|---|---|---|
| 0 | 写"读 ID"命令（地址 0x2F） | — | 从 ADC 数据模式进入寄存器模式 |
| 1 | RD 读回 | 期望 0x31 | AD7606C-16 的 ID |
| 2 | 写 0x07 BANDWIDTH | 0xFF | 8 路全部开 220 kHz 高带宽（每位一个通道） |
| 3 | 写 0x03 RANGE（CH1/CH2） | 0x33 | 每通道 4 位，`0011` = ±10 V 单端 |
| 4 | 写 0x04 RANGE（CH3/CH4） | 0x33 | 同上 |
| 5 | 写 0x05 RANGE（CH5/CH6） | 0x33 | 同上 |
| 6 | 写 0x06 RANGE（CH7/CH8） | 0x33 | 同上 |
| 7 | 写"读 BANDWIDTH"命令 | — | 准备回读 |
| 8 | RD 读回 | 期望 0xFF | 自检 |
| 9 | 写全 0 | 0x0000 | 退出寄存器模式，回到 ADC 数据模式 |

这些值是 `lock_in_amp.v` 里实例化驱动时传入的参数（`REG_BW`、`REG_RANGE12` 等），改量程改那里即可，
例如 `8'h11` 是 ±5 V。过采样寄存器没写，保持默认的不过采样，所以能跑满 1 MSPS。

### 4.3 每条操作的时序（16 个时钟周期，约 246 ns）

```
周期:   0      1                6      7         8 ~ 15
CS   ‾‾‾‾\________________________/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾
WR/RD‾‾‾‾‾‾‾‾\_________________/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾   （写用 WR，读用 RD）
DB    写：第 0 周期起 FPGA 驱动数据，第 7 周期释放
      读：第 6 周期采样
```

WR 低 5 个周期（77 ns，要求 ≥ 35 ns）；两次 WR 间隔 16 个周期（246 ns，要求 ≥ 180 ns）。

### 4.4 自检结果（上位机可见）

| 驱动输出 | 判断 | 正常值 | 帧内位置 |
|---|---|---|---|
| `cfg_done` | 10 条操作做完 | 1 | `lock_flags` bit2 |
| `cfg_err` | ID 高 4 位不是 3、地址回显不是 0x2F，或 BANDWIDTH 回读不是 0xFF | 0 | `lock_flags` bit3 |
| `frst_err` | 读数时 FRSTDATA 与通道序号不一致（粘滞） | 0 | `lock_flags` bit4 |
| `dev_id` | ID 回读值 | 0x31 | `lock_flags` bit[15:8] |

## 5. 循环采样（`ST_RUN`）

### 5.1 采样率

```144:144:project_1.srcs/sources_1/new/lock_in_amp.v
    .speed_set    (16'd64),   // 65 拍 → 1 MSPS
```

CONVST 周期 = `speed_set` + 1 = 65 个时钟周期 = 1 µs，即 **每个通道 1 MSPS**，8 路同时，不是平分。
驱动里还限制周期最短 1 µs（AD7606C 的最小转换周期），所以 1 MSPS 已是上限，只能调低。
降采样率时，下游 CIC 抽取比和 IIR 换算也要一起改。

| 项目 | 值 |
|---|---|
| 奈奎斯特频率 | 500 kHz |
| 芯片模拟带宽 | 220 kHz |
| 建议输入频率 | 200 kHz 以内 |

### 5.2 一个采样周期的时序

```
周期:     0   8         ~33~44        ~47 48                  ~95   65(下一轮 0)
CONVST  _/‾‾‾‾\_______________________________________________ _/‾‾‾‾\___
BUSY    __/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾\______________________________________/‾‾‾‾‾
CS      ‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾\____________________________________/‾‾
RD      ‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾\__/‾\__/‾\__/‾ ... \__/‾‾‾‾‾‾‾‾‾‾‾‾‾‾
DB                                  [V1][V2][V3] ...  [V8]
```

1. **启动转换**：每 65 个周期一个 CONVST 上升沿，高 8 个周期（123 ns）。8 路在这个边沿**同时采样**。
2. **转换**：BUSY 为高约 0.5~0.65 µs。
3. **检测完成**：BUSY 经 3 级寄存器同步，检测到下降沿后拉低 CS。
4. **读 8 次**：每个通道 6 个时钟周期，依次读 V1~V8，暂存到 `sh0`~`sh7`。
5. **一起更新**：8 个读完后，`data1`~`data8` 在同一个周期一起更新，`conv_done` 出一个周期的脉冲。

### 5.3 每读一个通道的时序（6 个周期，92.3 ns）

| 阶段 | 周期 | 时间 | 说明 |
|---|---|---|---|
| RD 低 | 4 | 61.5 ns | 芯片把数据放上总线（数据手册：RD 下降沿后最多 30 ns），留一倍余量 |
| 采样 | 第 4 周期末 | — | 存入对应的 `sh` 寄存器 |
| RD 高 | 2 | 30.8 ns | RD 高 ≥ 10 ns、RD 周期 ≥ 30 ns |

参数：`RD_LOW_CYC = 4`、`RD_HIGH_CYC = 2`。排线长、读数不稳时可把 `RD_LOW_CYC` 改为 5，时间仍够。

8 个通道共 48 个周期（约 0.74 µs），在 65 个周期内读完。

### 5.4 读数可以跨进下一轮

从 CONVST 算起，最后一个 RD 下降沿约在第 90 个周期，已进入下一个采样周期。
数据手册允许"Reading During Conversion"，只要读数不跨过下一次 BUSY 下降沿（芯片在这一刻更新输出寄存器）：
- 最后一个 RD 下降沿：不晚于第 90 个周期
- 下一次 BUSY 下降沿：不早于第 98 个周期（65 + 33）

### 5.5 可靠性设计

- **数据线在 IO 处打一拍**：`db_in_r` 标了 `(* IOB = "TRUE" *)`，寄存器放在引脚旁，时序稳定。
- **FRSTDATA 校验**：读 V1 时 FRSTDATA 应为高、其它为低，不一致就置 `frst_err`（粘滞），可发现漏读一个 RD 导致的错位。

### 5.6 数据先存在芯片里吗？

芯片内部每个通道只有一个**输出数据寄存器**，只保存最近一次转换的结果，下一次转换完成就覆盖。
它不是能攒很多点的缓存，所以 FPGA 必须在每 1 µs 内把 8 个值读走。

FPGA 里真正能缓存数据的只有示波器的 1024 点 BRAM（只存 V5/V6），其它通道进来就直接参与运算。

## 6. "8 路同时、1 MHz 更新"的准确含义

| 环节 | 8 路是否同时 | 速度 |
|---|---|---|
| 芯片采样 | **同时**（同一个 CONVST 边沿） | 1 MSPS |
| 芯片 → FPGA | **轮流**（一组数据线一次只能传一个通道） | 每 1 µs 读一轮，约 0.74 µs 读完 |
| 驱动输出 `data1`~`data8` | **同时**（读完后一起更新） | 1 MHz |

三种时间不要混淆：

| 时间 | 是什么 | 下游看得到吗 |
|---|---|---|
| 15.4 ns（1/65 MHz） | FPGA 时钟周期 | — |
| 92 ns（6 个周期） | 读一个通道，存入临时寄存器 | 看不到，只在驱动内部 |
| 1 µs（65 个周期） | `data1`~`data8` 一起更新一次 | 看得到 |

```
时钟周期:   |0      |65     |130    |195   ...  （每格 65 个周期 = 1 µs）
data1~8:   [ 第 n 组  ][ 第 n+1 组 ][ 第 n+2 组 ] ...
            ↑ 8 个值同时更新，之后保持 65 个周期不变
```

补充：
- 相对采样时刻，`data1`~`data8` 约晚 1.4 µs 更新，但 8 路延迟相同，不影响通道间相位。
- 下游运行在 65 MHz，同一组值被连续使用 65 个周期。
- "1 MHz"是更新频率，不要叫"拍频"（拍频在锁相里指差频）。

数据格式：16 位补码，±10 V 时 1 LSB ≈ 305 µV。示波器用全 16 位；锁相链取高 14 位 `[15:2]`
（1 LSB ≈ 1.22 mV），与原 14 位 ADC（AD9248）通路和 14×14 乘法器兼容。

## 7. 如果改用 SPI（串行接口）

### 7.1 引脚

PSB_SEL 跳到高后，部分并口引脚改为串口功能（AD7606C-16，以数据手册为准；模块上的对应关系需核对原理图）：

| 串口功能 | 复用的并口引脚 | 方向 |
|---|---|---|
| CS | CS | FPGA → 芯片 |
| SCLK | RD | FPGA → 芯片，最高 60 MHz（VDRIVE > 2.7 V） |
| SDI | DB11 | FPGA → 芯片（写寄存器） |
| DOUTA~DOUTD | DB7、DB8、DB9、DB10 | 芯片 → FPGA |
| DOUTE~DOUTH | DB3、DB4、DB5、DB6 | 芯片 → FPGA（8 线模式） |

### 7.2 读数据

- 每通道 16 位，高位在前，16 位补码，和并口格式相同。
- CS 下降沿送出 MSB，之后每个 SCLK 上升沿送出下一位。
- CONFIG 寄存器（0x02）bit[4:3] 选择 DOUT 线数：

| 线数 | 每根线依次输出 | 每次采样所需 SCLK |
|---|---|---|
| 1 | A：V1~V8 | 128 |
| 2 | A：V1~V4；B：V5~V8 | 64 |
| 4 | A：V1 V2；B：V3 V4；C：V5 V6；D：V7 V8 | 32 |
| 8 | 每线一个通道 | 16 |

硬件模式只能用 2 线。可选 8 位状态头和 8 位 CRC，打开后每通道 24 位。

### 7.3 能否跑满 1 MSPS

| 线数 | 需要的 SCLK | 60 MHz 上限下 | 65 MHz 二分频（32.5 MHz）时 |
|---|---|---|---|
| 1 | 128 MHz | ❌ 最高约 0.47 MSPS | ❌ |
| 2 | 64 MHz | ❌ 最高约 0.9 MSPS | ❌ |
| 4 | 32 MHz | ✅ 理论可行 | ⚠️ 需 0.985 µs，实际做不到 |
| 8 | 16 MHz | ✅ | ✅ 0.49 µs，余量充足 |

结论：保持 65 MHz、1 MSPS 时，串口模式只能用 8 根 DOUT。

### 7.4 寄存器访问

SDI 上每条命令 16 位，SCLK 下降沿移入：`WEN(=0) | R/W | ADD5~ADD0 | DIN7~DIN0`。
读任意寄存器进入寄存器模式；读寄存器分两帧（第一帧发地址，第二帧从 DOUTA 读内容）；
SDI 保持低 16 个 SCLK 回到 ADC 模式。

### 7.5 并口与串口对比

| 项目 | 并口（现在） | 串口（8 线） |
|---|---|---|
| FPGA 引脚 | 约 26 根 | 约 18 根 |
| 读 8 路时间 | 约 0.74 µs | 约 0.49 µs（32.5 MHz） |
| 时序难度 | 宽松 | 较紧 |
| 驱动 | 已有、已验证 | 需要重写 |
| 双向总线 | 有（BD 必须 Global 综合） | 没有 |

改为串口只需替换 `ad7606c_drv.v`，保持输出接口（`data1`~`data8`、`conv_done`、`cfg_done` 等）不变，
下游不用改；另需把 PSB_SEL 跳到高并修改 `pin_solidify.xdc`。

## 8. 锁相输出的更新速度

```
ADC 数据            混频               CIC 抽取 65 倍        IIR 低通            X / Y
(1 MHz 更新，  →   × sin/cos      →   65 MHz → 1 MHz   →   每 1 µs 算一次  →   每 1 µs 更新
 保持 65 周期)      每个时钟周期都算     每 65 周期出 1 个       (TAU, 阶数)         (dc_valid 脉冲)
```

- CIC 每个周期吃进一个混频结果（`s_axis_data_tvalid = 1`），每 65 个输出一个，`cic_valid` 为 1 MHz。
- IIR 以 `cic_valid` 为使能，输出 `dc_valid` 也是 1 MHz。七个振荡器、两路 PLL、DC 通路都一样。

**更新快不等于变化快**：X/Y 的信息带宽由 TAU 决定。

| TAU | 截止频率 | 含义 |
|---|---|---|
| 2 | 约 46 kHz | 几乎不滤波，2f 纹波明显 |
| 12 | 约 39 Hz | 相邻更新几乎相同 |
| 20 | 约 0.15 Hz | 几秒才跟上变化 |

```326:329:project_1.srcs/sources_1/new/usb_commend.v
            new_data_ready <= 1'b1;
```

在通道1 IIR 输出有效的上升沿（每 1 µs），若已 `XYOUT` 且不在发送中，就把 172 字节 + 4 字节 `frame_seq` 存入 `xy_data_reg`。
发送期间快照冻结，保证一帧内所有字段同一时刻。

**发送**：
1. 空闲时看到 `new_data_ready`，进入发送。
2. 从最高字节开始逐字节交给 `uart_link`，共 176 字节，边发边算 CRC16，再发 2 字节 CRC，**共 178 字节**。
3. 每字节 10 位（起始 + 8 数据 + 停止），928571 波特下约 10.8 µs，一帧约 **1.92 ms**。
4. 发完等 0.3 ms，再发最新快照 → 约每 2.22 ms 一帧，**约 450 帧/秒**。

多字节字段按大端发送；字节内低位先发（UART 惯例，由 CH340 处理）。
发送中收到命令的第一个字节会立即中止本帧去处理命令，PC 收到半帧，由 CRC 剔除。

### 9.2 示波器包（V5/V6 采样值）

V5/V6 原始值不在数据帧里连续发（需要约 4 MB/s，串口只有约 90 KB/s），只能分段抓取后整包上传。

**抓取**（`scope_cap.v`）：
1. 上位机依次发 `SDEC`（抽取）、`STLV`（触发电平）、`SCAP`（触发方式，启动一次抓取）。
2. 每次 `conv_done` 存一个点（有抽取时每 n+1 个存 1 个），每点 32 位 {V5, V6}，存入 1024 点 BRAM。
3. 先存满 128 点预触发，等触发（或 Auto 超时强制），再存 895 点，抓满后通知发送。

**上传**：状态机优先级为 处理命令 > 示波器包 > 数据帧。

| 部分 | 字节 |
|---|---|
| 同步头 `A5 5A 5A A5` | 4 |
| N、PRE、decim、标志（触发方式 + 是否强制）、保留、包序号 | 12 |
| 1024 点 × {V5, V6} | 4096 |
| CRC16 | 2 |
| **合计** | **4114（约 45 ms）** |

发送期间不收命令（暂存于 256 字节 RX FIFO），数据帧也暂停。一次 `SCAP` 只出一包。

### 9.3 三条示波器命令

| 命令 | 作用 | 类比示波器 |
|---|---|---|
| `SDEC:n` | 每 n+1 点存 1 个，dt = (n+1) µs | 时基旋钮 |
| `STLV:码` | 触发电平，码 = 电压 × 3276.8 + 32768 | 触发电平旋钮 |
| `SCAP:模式` | **启动一次抓取** + 选择触发方式 | Single 按钮 + 触发方式 |

`SCAP` 不控制速度。它的参数：0 立即；1/2 V5 上升/下降沿；3/4 V6 上升/下降沿；加 8 为 Normal（不强制触发）。
`SDEC`、`STLV` 要在 `SCAP` 之前发，FPGA 在收到 `SCAP` 时锁存设置。

### 9.4 PC 收到的字节流

```
...[帧 178B][帧 178B]["Command Success!\r\n"][帧 178B][半帧][帧 178B][示波器包 4114B][帧 178B]...
```

没有额外的长度字段或分隔符，接收端靠两种同步头、固定长度和 CRC 区分。

## 10. 上位机怎么控制和接收

### 10.1 GUI（`lockin_gui`）

**连接**：打开串口，发 `stop` 握手（最多 3 次，每次等 0.3 s）。此时未开数据流，命令都"发一条、读应答"。

**开始数据流**：
1. 发 `XYOUT`，启动后台线程 `_rx_loop`（每次读最多 512 字节），由 `StreamParser` 拆帧。
2. `FrameTracker` 用 `sample_cnt` 生成 FPGA 时间轴，再交给主窗口 `on_frame`。
3. **数据流开着时，GUI 发命令只写不读**（不等应答），因为 pyserial 在 Windows 上两个线程同时读同一串口会崩溃。

**主窗口每帧处理**：

| 处理 | 频率 |
|---|---|
| 最新频率、锁定状态 | 每帧（约 450 次/秒） |
| 曲线缓冲与 CSV 存盘 | 按"抽样"比例：100% / 50% / 25% / 10% / 1% |
| 文字标签 | 最多 30 次/秒 |
| 曲线重绘 | 15 次/秒，每条显示最近 1000 点 |

**示波器窗口**：
1. 必须先开数据流（示波器包由同一接收线程解析）。
2. "运行"/"单次"时依次发 `SDEC` → `STLV` → `SCAP`。
3. 收到一包就画图；运行模式下距上一包至少 50 ms 后再发 `SCAP`（最快约 20 张/秒）。
4. 看门狗每 500 ms 检查：超过（Auto 1 s / Normal 3 s）+ 3 倍一屏时长没收到包就重发 `SCAP`。

### 10.2 C++ SDK（`lockin_sdk_cpp`，经典）

**线程结构**：

```
你的线程                               SDK 接收线程（open 时启动，一直运行）
─────────────                         ──────────────────────
setOscFrequency() 等                   循环：port.read(最多 4096 字节)
  └─ command()：                         └─ feed()
      加锁、发 "CMD\r\n"                      ├─ ① 扫描应答文字 → 计数 +1，唤醒命令
      等应答（最多 500 ms） ◀──────────────────┘
                                              ├─ ② 找 A5 5A A5 5A → 数据帧
captureScope()                                │      满 178 B 且 CRC 对 → 解码 → latestFrame → 帧回调
  └─ 等示波器包 ◀──────────────────────────────┤
                                              └─ ③ 找 A5 5A 5A A5 → 示波器包
latestFrame() 随时读最新一帧                         包头合理、收满、CRC 对 → 解码 → 唤醒 captureScope → 示波器回调
```

**解析**（`feed()`）：
1. 在原始字节里搜 `Command Success!` / `Command Error!`（跨读取截断也能拼接）。
2. 字节追加到缓冲区，找最近的同步头：
   - 数据帧：不足 178 字节就等；CRC 通过则按大端解码为 `Frame`；失败只跳过 1 字节继续找，CRC 错误计数 +1。
   - 示波器包：检查包头（N 为 2 的幂、PRE < N），收满后校验 CRC，解码为 `ScopeData`（含电压和时间轴）。
3. 保存为最新数据，调用用户回调。

**发命令**：所有设置函数调用 `command()`，加互斥锁排队，发 `命令\r\n`，等应答计数 +1（最多 500 ms）。
`Success` 返回 true；`Error` 或超时返回 false，原因见 `lastError()`。
**不能在回调里发命令**（回调在接收线程上，等应答会卡死），SDK 会直接拒绝。

**与 GUI 的区别**：

| 项目 | GUI | SDK |
|---|---|---|
| 接收线程 | 开数据流时才启动 | `open()` 时启动，一直运行 |
| 数据流中发命令 | 只写不读，不确认 | 始终等应答，可确认成功 |
| 抓示波器 | 必须先开数据流 | 不需要开数据流 |

**用法示例**：

```cpp
// 锁相数据
dev.startStream();                                   // XYOUT
dev.setFrameCallback([](const lockin::Frame& f) {    // 约 450 次/秒，在接收线程里
    double r = f.oscRVolts(0);                       // 振荡器1 幅度（V）
});
lockin::Frame f;
if (dev.latestFrame(f)) { /* 或随时取最新一帧 */ }
dev.stopStream();                                    // stop

// V5/V6 波形（单次）
lockin::ScopeConfig cfg;
cfg.decimation = 9;                                  // dt = 10 µs，一屏 10.24 ms
cfg.trigger    = lockin::ScopeTrigger::V5Rising;
cfg.levelVolts = 0.0;
lockin::ScopeData sd;
if (dev.captureScope(sd, cfg, 3000)) {               // SDEC → STLV → SCAP，阻塞等包
    // sd.v5[i]、sd.v6[i]（V），sd.timeAt(i)（s）
}
```

`captureScope` 超时前没等到包会自动重发 `SCAP`，并忽略抽取或触发方式不符的旧包。
连续刷新可用 `setScopeCallback` + 反复 `armScope`。

### 10.3 Osc1 精简 SDK（`lockin_sdk_osc1`）

发 `SDKOUT` 后解析同步头 `A5 5A C3 01` 的 **28 字节帧**（osc1 X/Y + V3/V4/V5 + sample_cnt + frame_seq + CRC）。
控制 API 仅覆盖振荡器1 与 DAC；**没有** `captureScope` / 1024 点包——示波器数据就是每帧里的 V3/V4/V5 瞬时值。
串口约 **2 k 帧/秒**。详见该目录 `README.md` 与协议 §5.3。

```cpp
#include <lockin_osc1/lockin_sdk.h>
using namespace lockin_osc1;
LockinDevice dev;
dev.open();
dev.setOsc1Frequency(10e3);
dev.setDacSourceOsc1();
dev.startStream();   // SDKOUT
Frame f;
if (dev.latestFrame(f))
    use(f.osc1RVolts(), f.v3Volts(), f.v4Volts(), f.v5Volts());
```

### 11.2 示波器

|---|---|
| ADC 采样 | 1 MSPS，一直在采 |
| 存入 BRAM | 1 MHz / (SDEC+1)，只在 `SCAP` 后、抓满前 |
| 一屏时长 | 1024 × (SDEC+1) µs |

## 12. 使用要点

1. **瓶颈是串口**：硬件每秒算 100 万次，串口每秒只送出约 450 帧。要更高数据率只能换以太网、提高波特率或缩短帧。
2. **TAU 配合 450 帧/秒**：X/Y 截止频率最好低于约 225 Hz，否则上位机曲线出现假的低频波动（混叠）。建议 TAU ≥ 12。
3. **GUI 抽样只是丢帧，不做平均**：抽到 10% 时有效速率只有 45 点/秒，TAU 应 ≥ 13（截止频率 < 22 Hz）。
4. **时间轴用 `sample_cnt`**：GUI 已如此；SDK 用户请用 `Frame.sampleCount`（1 µs/计数），不要用 PC 接收时间。
5. **示波器与数据流共用串口**：每传一包示波器数据，数据流停约 45 ms（少约 20 帧）；示波器连续刷新时数据帧速率明显下降。
6. **上电先看 `lock_flags`**：bit2 = 1、bit3 = 0、bit4 = 0、ID = 0x31，说明 ADC 跳线、接线、配置都正常。
