# 02 通信协议（串口版，权威）

> 依据代码：`usb_commend.v`（命令解析 / 打包）、`lock_in_amp.v`（帧字段）、`scope_cap.v`（示波器）、
> `uart_link.v`（链路）。代码与本文不一致时**以代码为准**，并请更新本文。

## 1. 物理链路

| 项目 | 值 |
|---|---|
| 接口 | 板载 CH340 USB 转串口（PC 端是一个 COM 口） |
| FPGA 引脚 | L17 = `uart_txd_0`（FPGA 发）、M17 = `uart_rxd_0`（FPGA 收，内部上拉） |
| 格式 | 921600 波特，8 数据位，无校验，1 停止位，无流控 |
| 实际波特率 | 65 MHz / 70 = 928571（比标称快 0.76%，在容限内） |
| 方向 | 下行：ASCII 命令；上行：ASCII 应答 + 二进制数据帧 + 二进制示波器包，**混在同一字节流里** |

串口是独占的：GUI、SDK、串口助手同一时间只能有一个打开该 COM 口。

## 2. 命令格式

```
NAME:十进制数字\r\n        带参数命令，例如  FRQ21:692861481134\r\n
XYOUT                      无参数，收到最后一个字母 T 立即执行
stop                       无参数（小写），收到最后一个字母 p 立即执行
```

解析规则（来自 `usb_commend.v` 状态机）：

- 命令名区分大小写，长度 2~7 个字符，后跟 `:`。超过 8 个字符仍未匹配 → 回 `Command Error!`。
- 数字部分只认 `0`~`9`，**其它字符（包括负号 `-`、空格）被静默忽略**；遇到 `\r` 或 `\n` 才执行。
  因此不能发负数，需要负值的参数（`DOFS`）使用补码编码。
- 数值缓冲 48 位，超出会回绕；各命令只取需要的低位（见命令表）。
- 空闲时收到的多余 `\r` / `\n` 被忽略，所以 `\r\n` 两个字节都发也没问题。
- 数据流发送中收到**非 CR/LF** 字节会立即打断当前数据帧，转去解析命令。

## 3. 应答

| 情况 | 应答内容 | 字节数 |
|---|---|---|
| 识别并执行 | `Command Success!\r\n` | 18 |
| 命令名不认识 | `Command Error!\r\n` | 16 |

- 参数越界**不会**回错误：多数命令按位截取，部分命令钳位或忽略（见命令表"越界处理"列）。
- 发应答期间 FPGA 不读串口，后续字节暂存在 256 字节 RX FIFO 里，应答发完再处理。
- 上位机应**发一条、等应答、再发下一条**（GUI 和 SDK 都这样做，SDK 超时 500 ms）。
- 应答夹在二进制数据流中间，上位机用正则 `Command (Success|Error)!` 匹配，不依赖结尾换行。

## 4. 命令表

频率字 = round(f[Hz] × 2⁴⁸ / 65 000 000)，48 位无符号。

### 4.1 数据流

| 命令 | 参数 | 作用 |
|---|---|---|
| `XYOUT` | 无 | 开始周期上传数据帧 |
| `stop` | 无 | 停止数据帧（示波器包不受影响） |

### 4.2 锁相环（通道1 / 通道2）

| 命令 | 参数 / 取位 | 默认值 | 说明 |
|---|---|---|---|
| `FRQ2` | 48 位频率字 | 433471464133（≈100.1 kHz） | 通道1 PLL 扫频起点 |
| `FRQ3` | 48 位频率字 | **无复位值（上电为 0）** | 通道2 PLL 扫频起点，见已知问题 |
| `KP` | 16 位 | 500 | PI 比例系数（两通道共用） |
| `KI` | 16 位 | 50 | PI 积分系数（两通道共用） |
| `TAU1X` / `TAU1Y` | 5 位（0~31） | 20 / 8 | 通道1 X（幅值）/ Y（相位误差）IIR 档位 |
| `TAU2X` / `TAU2Y` | 5 位 | 20 / 8 | 通道2 同上 |
| `LOCKSWY` | 28 位 | 100000 | 扫频中 \|Y\| 超过它 → 进入锁定 |
| `LOCKTHX` | 28 位 | 300000 | 锁定中 \|X\| 持续低于它（约 2 s）→ 退回扫频 |
| `FREQ` | 48 位 | 433038425708 | **未使用**（保留连线，不影响 PLL） |
| `PHAS` | 48 位 | 0 | **未使用** |

PLL 扫频范围：起点 ±10 kHz，步进约 10 Hz，每 0.5 ms 一步（硬编码在 `pll_controller.v`）。

### 4.3 振荡器 1~7（通道3 解调）

`k` = 振荡器编号。振荡器1/2/3 的 FRQ/TAU/ORD 用历史名 `21`/`12`/`11`，其余用 `4`~`7`：

| 振荡器 | 频率 | 时间常数 | 阶数 | 系数 | 谐波次数 | 输入 |
|---|---|---|---|---|---|---|
| 1 | `FRQ21` | `TAU21` | `ORD21` | `OSC1` | `OHN1` | `OSRC1` |
| 2 | `FRQ12` | `TAU12` | `ORD12` | `OSC2` | `OHN2` | `OSRC2` |
| 3 | `FRQ11` | `TAU11` | `ORD11` | `OSC3` | `OHN3` | `OSRC3` |
| 4~7 | `FRQk` | `TAUk` | `ORDk` | `OSCk` | `OHNk` | `OSRCk` |

| 命令 | 参数 / 取位 | 越界处理 | 默认值 |
|---|---|---|---|
| `REFMODE` | bit0：0 = 手动，1 = 自动 | 只取 bit0 | 0（GUI 连接后会发 1） |
| `FRQxx` | 48 位频率字（手动模式基频） | 截取 | 160/170/110/150/180/220/200 kHz |
| `OHNk` | 8 位，谐波次数 N | 0 当作 1 | 1 |
| `OSCk` | n×256 + m（n、m 各 0~255） | 截取 | (2,1)(1,2)(1,1)(3,0)(0,3)(2,2)(4,0) |
| `OSRCk` | 0 = V3，1 = V4，2 = V3−V4（饱和） | 只看低 2 位，等于 3 时**保持原值** | 0 |
| `TAUxx` | 5 位（0~31），α = 2^-tau | 截取 | 2 |
| `ORDxx` | 1~4 阶 | 其它值当作 1 | 1 |

参考频率：

- 手动（`REFMODE:0`）：f_ref = `FRQxx` × `OHNk`
- 自动（`REFMODE:1`）：f_ref = `OHNk` × (n·F1 + m·F2)，F1、F2 为两路 PLL 锁定频率，且与输入相干
- 实际生效的参考频率字在数据帧 `ref_word` 字段回读

注意：`OSRCk` 取的是低 2 位，所以发 `4` 等于发 `0`，发 `5` 等于发 `1`。

### 4.4 DC 通路

| 命令 | 参数 | 默认值 |
|---|---|---|
| `TAUDC` | 5 位 | 2 |
| `ORDDC` | 1~4（其它当作 1） | 1 |

### 4.5 DAC 信号发生器

| 命令 | 参数 / 取位 | 默认值 | 说明 |
|---|---|---|---|
| `DMOD` | 3 位，0~6 = 振荡器1~7 | 0 | 选择输出哪个振荡器的参考正弦（发 7 等同于 0） |
| `DWAV` | bit0：0 = 正弦，1 = 方波 | 0 | 方波 = 正弦取符号 |
| `DAMP` | 16 位，0~65535 | 65535 | 幅度 = 参考 × DAMP/65536；65535 ≈ 3.0 Vpk |
| `DOFS` | 14 位补码（-8192~8191） | 0 | 直流偏置；负数发 `值 & 0x3FFF`，例如 -1 发 16383 |
| `DFRQ` / `DPHS` | — | — | **已废弃**：回 Success 但不起作用（频率、相位跟随振荡器） |

### 4.6 示波器（V5 / V6）

| 命令 | 参数 | 说明 |
|---|---|---|
| `SDEC` | 16 位，抽取 n | 每 n+1 个样点存 1 个（不平均），dt = (n+1) µs |
| `STLV` | 偏移码：电平码 + 32768 | 触发电平；电平码 = 电压 / (10/32768)，例如 1 V → 36045 |
| `SCAP` | bit[2:0] 触发方式，bit3 = 1 表示 Normal | 启动一次抓取（**每次抓取都要发**） |

`SCAP` 触发方式：0 = 立即，1 = V5 上升沿，2 = V5 下降沿，3 = V6 上升沿，4 = V6 下降沿（大于 4 当作 0）。
bit3 = 0 为 Auto（超过 max(100 ms, 一屏时长) 无触发就强制触发），bit3 = 1 为 Normal（一直等）。
例：`SCAP:1` = V5 上升沿 Auto；`SCAP:9` = V5 上升沿 Normal。

`SDEC`、`STLV` 要在 `SCAP` **之前**发：抽取和触发方式在 `SCAP` 时锁存，并随数据包回传。

## 5. 上行数据帧（178 字节，大端）

`XYOUT` 后，FPGA 在 1 MHz 的通道1 IIR 输出节拍上锁存一次快照，空闲时发出；
每帧发完等 19500 拍（0.3 ms）再发下一帧。

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | 同步头 | 4 B | `A5 5A A5 5A` |
| 4 | ch1_x, ch1_y, ch2_x, ch2_y | 4 × int32 | PLL 通道1/2 的 X/Y |
| 20 | osc1~osc3 的 X, Y | 6 × int32 | 顺序 x21, y21, x12, y12, x11, y11 |
| 44 | osc4~osc7 的 X, Y | 8 × int32 | |
| 76 | ch3_dc | int32 | V3 DC 通路 |
| 80 | adc_ch1, adc_ch2, adc_ch3 | 3 × int32 | V1/V2/V3 瞬时值（14 位符号扩展） |
| 92 | pll_word_ch1, pll_word_ch2 | 2 × uint64 | PLL 锁定频率字（低 48 位有效） |
| 108 | lock_flags | int32 | 见下表 |
| 112 | ref_word osc1~osc7 | 7 × uint64 | 七路实际参考频率字 |
| 168 | sample_cnt | uint32 | 1 MHz 节拍计数（约 71.6 分钟回绕） |
| 172 | frame_seq | uint32 | 帧序号 |
| 176 | CRC16 | 2 B | 覆盖偏移 0~175，高字节在前 |

Python 解析：`struct.unpack(">19i3iQQi7QII", buf[4:176])`。

`lock_flags`：

| 位 | 含义 |
|---|---|
| 0 | 通道1 PLL 锁定 |
| 1 | 通道2 PLL 锁定 |
| 2 | AD7606C 寄存器配置完成（正常 = 1） |
| 3 | AD7606C 配置回读错误（正常 = 0） |
| 4 | FRSTDATA 错位（正常 = 0） |
| 15:8 | AD7606C ID 寄存器回读（正常 0x31） |

### 5.1 换算到物理量

| 量 | 公式 |
|---|---|
| 频率 | Hz = word × 65e6 / 2⁴⁸ |
| X/Y → 输入幅度（V） | X × 0.9966 / G，G = (8192/9.75) × 8192 × 0.5 × (65⁵/2³¹) ≈ 1 859 440，约 5.36e-7 V/LSB |
| R、相位 | R = √(X²+Y²)，θ = atan2(Y, X) |
| ch3_dc → V | ch3_dc / ((8192/9.75) × 65⁵/2³¹) ≈ ch3_dc × 2.203e-3 |
| adc_chN → V | adc × 10 / 8192 |
| sample_cnt → s | × 65/65e6（标称 1 µs） |

9.75 V 是实测标定出的 ADC 等效满量程（不是面板量程 10 V），0.9966 是与 Zurich 锁相放大器对比后的幅度修正。
GUI 的"时基标定"是另一回事：它修正晶振 ppm 偏差，只影响频率换算，不影响幅度。
以上常数在 `lockin_gui/main_window.py` 开头定义，SDK 里可用 `setVoltsPerLsb()` 覆盖。

### 5.2 帧速率与半帧

- 一帧 178 字节 × 10 bit / 928571 = 1.92 ms，加 0.3 ms 间隔 ≈ 2.22 ms，约 **450 帧/秒**。
- 命令打断帧时 PC 会收到半帧；下一个同步头出现时，这段数据长度不够或 CRC 不对，被丢弃。
  GUI / SDK 都统计 CRC 错误数，**发命令期间出现少量 CRC 错误是正常现象**。
- `frame_seq` 在每次锁存快照时 +1，而帧间隔期间也会锁存，所以相邻帧的序号差通常大于 1。
  用它算"丢帧"会偏多，只适合看是否有大段中断。

## 6. 上行示波器包（4114 字节，大端）

`SCAP` 抓满 1024 点后，FPGA 在空闲且 RX FIFO 为空时发出整包，**发送期间不收命令**（约 45 ms）。

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | 同步头 | 4 B | `A5 5A 5A A5`（注意与数据帧不同） |
| 4 | N | uint16 | 点数，1024 |
| 6 | PRE | uint16 | 预触发点数，128（触发点下标） |
| 8 | decim | uint16 | 本次抓取锁存的 SDEC |
| 10 | flags | uint8 | bit[3:1] = 触发方式，bit0 = 强制触发 |
| 11 | 保留 | uint8 | 0 |
| 12 | seq | uint32 | 示波器包序号 |
| 16 | 样点 | N × (int16 V5, int16 V6) | 按时间顺序 |
| 16+4N | CRC16 | 2 B | 覆盖前 16+4N 字节 |

- 电压 = 码 × 10/32768；时间 t[i] = (i − PRE) × (decim+1) µs。
- 包头不含 Normal/Auto 位，上位机要自己记住发的是哪种。
- 一次 `SCAP` 只出一包；要连续刷新就反复发 `SCAP`。

## 7. CRC16

CRC-16/CCITT-FALSE：多项式 0x1021，初值 0xFFFF，不反射，无输出异或。
Python：`binascii.crc_hqx(data, 0xFFFF)`；校验值 `crc("123456789") = 0x29B1`。

## 8. 典型会话

```
PC → stop\r\n                    FPGA → Command Success!\r\n    (确认连通，同时停掉旧数据流)
PC → REFMODE:0\r\n               FPGA → Command Success!\r\n
PC → FRQ21:43303842571\r\n       FPGA → Command Success!\r\n    (振荡器1 = 10 kHz)
PC → OHN1:1\r\n                  FPGA → Command Success!\r\n
PC → DMOD:0\r\n                  FPGA → Command Success!\r\n    (DAC 输出振荡器1)
PC → XYOUT                       FPGA → Command Success!\r\n  然后 [178 B 帧][178 B 帧]...
PC → SDEC:9\r\n                  (打断当前帧) → Command Success!\r\n → 继续出帧
PC → SCAP:1\r\n                  → Command Success!\r\n → ...帧... → [4114 B 示波器包] → ...帧...
PC → stop\r\n                    → Command Success!\r\n  (数据流停止)
```
